# Word 변경 추적: 오류 대처와 한계

`track_changes.py`가 오류를 내거나, 표·각주·텍스트 상자처럼 편집되지 않는 곳을 확인할 때 읽는다.

## 1. 오류 메시지와 대처

해석에 하나라도 실패하면 파일을 쓰지 않는다(`--skip-errors`는 실패한 항목만 빼고 진행).

| 메시지 | 대처 |
|---|---|
| '…'을(를) 찾지 못했습니다 | `extract` 결과에서 글자를 그대로 복사한다. 따옴표 모양(“ ” vs " ")과 띄어쓰기를 확인한다 |
| '…'이(가) N번 나옵니다 | `para`를 주거나, `occurrence`를 주거나, 앞뒤 글자를 늘린다 |
| 개체 표식의 순서나 개수가 다릅니다 | 새 글에 ⟦…⟧ 표식을 원문과 같은 순서로 넣는다 |
| 기존 변경 추적 구간과 겹칩니다 | 다른 사람이 넣은 삽입 구간은 고칠 수 없다. 옆 글자만 고치거나, 사용자에게 먼저 수락·거부를 권한다 |
| 편집 N·M의 수정 범위가 겹칩니다 | 두 편집을 하나의 `rewrite`로 합친다 |
| 바로 뒤에 합칠 문단이 없습니다 | 표·구역 경계는 합칠 수 없다. 문장만 고친다 |
| 문단 나누기 위치가 수정 범위 안입니다 | 나누기 위치를 바꾸거나 수정 범위를 줄인다 |

## 2. 보존되는 것과 한계

보존: 런 서식(굵게·기울임·밑줄·색·글꼴), 문단 스타일·번호 목록·들여쓰기, 표 구조, 각주·미주, 하이퍼링크(링크 글자와 주소), 책갈피, 필드, 그림, 머리글·바닥글, 기존 메모와 다른 사람의 변경 기록, 문서 설정.

한계:

- 텍스트 상자·도형 안 글, 수식 안 글은 편집하지 않는다(`extract`가 경고).
- 서식만 바꾸는 변경(굵게 풀기 등)은 기록하지 않는다. 글자 수정만 다룬다.
- 필드 결과 글자, 문단 경계를 넘는 필드(목차) 안쪽은 편집하지 않는다.
- 하이퍼링크 글자 끝에 바로 붙여 쓴 글자는 링크 **바깥**에 들어간다(링크를 늘리지 않음).
- 문단을 합칠 때 두 문단의 스타일이 다르면 앞 문단 스타일을 따른다(엔진이 경고).
- 구형 .doc, .odt, 암호가 걸린 문서는 직접 다루지 않는다. .doc은 LibreOffice로 .docx 변환 뒤 작업하되 변환 과정의 서식 변화를 사용자에게 알린다.
- Microsoft Word 자체로 연 시험 대신 XML 스키마 검사와 LibreOffice 렌더링으로 검증한다.
